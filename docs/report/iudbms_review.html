00The unit of evidence

Everything the system knows arrives as lines like this, from /sys/kernel/debug/usb/usbmon/0u.

f5ca4980 3854346339 C Ii:1:003:1 0:4 8 = 00001600 00000000

Ii:1:003:1interrupt IN, bus 1, device 3, endpoint 1

This exact line is why the capture layer was rewritten. The prototype read the polling interval as the transfer length, and silently dropped four real line forms — every submission, every uncaptured payload, control setup packets, and isochronous completions.

03The two mimicry adversaries

Both clone a keyboard descriptor and draw keystroke timing from the same distribution as a human operator — a Kolmogorov–Smirnov test cannot separate their inter-arrivals from benign typing. They differ in one respect, and it decides everything.

The bound: an unbounded human-paced payload is undetectable

Push the adversary one step further — a payload of unbounded length drawing fresh keycodes forever — and it becomes statistically the benign keyboard process. A per-feature Kolmogorov–Smirnov scan separates it on zero of the 28 deployed features. That is a bound on what single-device HID behaviour can reveal, not a tuning failure, and it is documented rather than simulated: a corpus profile indistinguishable from benign by construction teaches a model nothing.

The principled next defence is cross-device correlation — a human typing produces concurrent mouse activity, a BadUSB typing alone does not. That sits outside the current single-device architecture.

Four pillars, and until now only three ablations. Isolating the device baseline by setting its fusion weight to zero — forest only, same score scale — gives:

Removing the baseline leaves detection unchanged within noise — two sessions of 120 — and marginally better. Its AUC contribution is negative at both levels. The one place it looks decisive, Stage-1-only rising from 0.0 % to 15.8 %, is a threshold artefact: with near-identical AUC the baseline shifts the score distribution so a fixed operating point lands better. That is fragile, not a capability.

A plausible explanation, offered as hypothesis rather than defence: the forests are already class-conditioned, so a device’s class-specific normality is largely captured at population level, leaving little for a per-device term on a corpus where devices within a class are near-identical. Real devices vary more.

06Findings from measuring what had been assumed

Thirteen defects found so far. Each was invisible in every previously reported number, and most surfaced only by running an ablation, a sweep, or a screen whose result had already been assumed.

A leak that survived being fixed once

Aggregate agreement is not evidence

Session durations matched in aggregate — 63.7 s benign against 63.9 s malicious — which is exactly why the earlier fix looked complete. Per profile they did not: staged_delay drew 65–85 s against everyone else’s 40–85. The audit now runs per profile, and a test re-introduces the original bug to prove the audit still catches it.

A test that could no longer fail

The audit went blind and kept saying “ok”

Adding a sixth attack profile dropped per-profile sample size, and the KS critical value scales as 1/√n — so the leak-detection test began passing because the audit could no longer fail. It now reports UNDERPOWERED when a profile’s critical value exceeds the effect it claims to detect, and says how many sessions it would need.

Found by looking at live data

The dashboard’s first screen said a z-score of 4,472,091

Three features are exactly constant across benign traffic, so standardising divided by roughly zero and a single 0→1 flip swamped every other dimension. Bounding it left the headline intact but collapsed the Stage-1 ablation — because its old score was substantially an artefact.

A sweep laundering noise into a decision

The winner on the selection split lost the test split

A longer sequence horizon won the selection split by two points — over fifty attack sessions, that is one session. Applied to test it scored five points worse. A detection rate over n sessions cannot resolve differences smaller than 1/n, so the sweep now compares against the incumbent and recommends KEEP unless the margin clears the noise floor.

The incumbent was restored because the margin was insignificant — a judgement available from the selection split alone — and not because the test number was better. Choosing on the test result is precisely what this harness exists to prevent.

07What this does not yet show

  • No real USB traffic. The parser is validated against real kernel line formats including four the prototype silently dropped, but nothing here has seen live traffic.
  • Attack families come from the code the features were designed against. Per-class rates are optimistic by construction; test counts are 15–24 sessions each.
  • Feature 29 was designed against a known failure. The constraint it exploits is real — an injection payload must type specific commands — but an adversary who pads or reorders degrades it. It raises cost; it does not solve.
  • Multi-modal fusion (N1) is unsupported by this evidence.
  • Enforcement has never executed. Four interlocks guard it and the review flag is still false.
  • eBPF is unstarted and may remain documented future work.
