L0 / L1

Capture and normalisation

src/iudbms/capture/

Turning the kernel's text log into typed event records. No learning here — but two of the project's eight defects lived in this layer, because everything downstream inherits its mistakes silently.

01usbmon line tokenisation

Parse one usbmon text line into a URB event.

tokens := line.split() tag ts evt <type><dir>:<bus>:<dev>:<ep> status-word [iso-desc] length [tag data…] status-word takes one of two shapes: s bmRequestType bRequest wValue wIndex wLength ← control submission (SETUP) status[:interval[:start_frame[:error_count]]] ← everything else data tag: = means payload words follow; - < > mean not captured

Parsing is whitespace tokenisation, not a regular expression. The optional fields in the status word produce a combinatorial explosion that makes a single pattern both slower and far harder to audit; tokenisation also degrades gracefully on fields we do not model — isochronous frame descriptors — by scanning forward for the data tag rather than failing.

Why it matters

The Sprint-0 regex silently dropped four real line forms: every submission, every uncaptured payload, control setup packets, and iso completions with a four-part status word. It also read the polling interval as the transfer length, because 0:8 followed by 8 is ambiguous unless you know the grammar. Both are now fixture-asserted against lines from the kernel documentation.

02Timestamp rebasing and counter wrap

Convert kernel microsecond stamps into seconds since enumeration.

if rawₕ < prevₕ − 2³¹: wraps ← wraps + 1 ← backward jump = wrap, not reordering absₕ := rawₕ + wraps · 4096·10⁶ t := (absₕ − originₕ) / 10⁶

usbmon text timestamps are CLOCK_MONOTONIC with the seconds truncated to 12 bits (mon_text.c: (tv_sec & 0xFFF)·10⁶ + µs), so they wrap every 4096 s (68.3 min), not at 2³² µs. A backward jump larger than half the range is treated as a wrap; anything smaller is treated as genuine reordering and left alone.

03Descriptor scan with arrival tracking

Record what each device claims to be, and when that claim changed.

for each rescan of /sys/bus/usb/devices: first_seen[dev, iface] := first_seen.setdefault(dev, iface, now) visible_at(t) := { i ∈ interfaces : i.first_seen ≤ t }

Interface directories appear as the host enumerates them, so re-scanning periodically is how a device that grows an interface mid-session becomes visible. Storing a per-interface arrival time makes visible_at(t) a total function.

Why not a single flag

The prototype kept one late_iface_ts on the descriptor and reconstructed visibility as interfaces[:-1] — correct only when exactly one interface arrives late and it happens to sort last. A composite device adding two, or adding one that is not last, was silently mis-described.

L2

Feature extraction — 29 dimensions, four modalities

src/iudbms/features/extractor.py

Each one-second window becomes a fixed vector. Features are computed over completions and errors only, never submissions: every submission has a matching completion, so counting both doubles every rate while adding no information and makes the result depend on kernel scheduling rather than device behaviour.

04Tumbling window assignment

Bucket events into non-overlapping one-second windows.

index(e) := ⌊ e.ts / stride ⌋ n_windows := max(1, ⌊t_last/stride⌋ + 1, ⌈duration/stride⌉)

Window length 1.0 s with stride 1.0 s. Chosen so an injection burst of ~200 keystrokes/second is unmistakable inside one window, while a human typist's natural pause does not empty it.

The two lower bounds on the window count round differently and both are needed: an event at exactly t = 4.0 belongs to window 4 and so requires five windows, whereas covering the interval [0, 4) requires only four. Empty windows are emitted, never skipped — an idle second is a real observation about a device.

05Inter-arrival moments

Nine timing features summarising how the device paces its traffic.

Δ := diff(sorted timestamps) mean, std, min, p10 of Δ cv := std(Δ) / mean(Δ) ← scale-free regularity rate := n / window

The coefficient of variation is the discriminative one: programmatic injection holds a near-constant inter-arrival (cv < 0.05), while human typing is heavy-tailed (cv ≈ 1). Because it is a ratio it does not care whether the device is fast or slow, only whether it is regular.

A window with fewer than two events has no inter-arrival at all. Those features report the full window length rather than zero, so that silence does not masquerade as infinite speed to a downstream scaler.

06Normalised arrival entropy

How many distinct timing regimes appear in one window.

bin log₁₀Δ into 12 bins over [−4, 1] ← 100 µs … 10 s pᵢ := hᵢ / Σh H := −Σ pᵢ ln pᵢ / ln 12 ← normalised to [0, 1]

Working in log-space is what makes this meaningful: USB inter-arrivals span five orders of magnitude, from a 125 Hz mouse to multi-second human pauses, and a linear histogram would put almost everything in one bin. Dividing by ln 12 normalises against the bin count so the value is comparable across configurations.

07Fano factor (burstiness)

Distinguish a steady stream from the same volume delivered in bursts.

split the window into 10 sub-windows of 0.1 s cᵢ := event count in sub-window i F := Var(c) / Mean(c) F ≈ 0 perfectly regular F ≈ 1 Poisson F ≫ 1 bursty

Event rate alone cannot separate a device that sends 50 events evenly from one that sends 50 in a single 100 ms burst. The Fano factor is the standard index of dispersion for a counting process and it separates them directly. Human typing is bursty (words then pauses); injection is close to regular.

08Payload novelty and repeat ratio

Within-window payload diversity.

P := [ e.data for e in window if e.data ] ← captured payloads only novelty := |distinct(P)| / |P| repeat_ratio := max count(p) / |P|
Known limitation

These two do not separate a replayed keystroke script from a human, because both draw keycodes from a similar alphabet and a one-second window holds only about five mostly-distinct keystrokes. That limitation is precisely what motivated algorithm 09.

Only events with a captured payload participate. Counting the ones the kernel declined to capture would make an uncaptured bulk stream look like a perfectly repeating one — the conflation that URBEvent.data_truncated exists to prevent.

09Payload sequence novelty — the cross-window feature

Detect a replayed script by exhaustion of its own transitions.

seq := [last payload of previous window] ++ payloads of this window B := { (seqᵢ, seqᵢ₊₁) } ← consecutive payload pairs novelty := |{ b ∈ B : b ∉ seen }| / |B| ← judged BEFORE insertion seen := seen ∪ B ← capped at 8192 entries

Order is the signal, not the alphabet. A keystroke injection payload replays a predetermined sequence, so after one cycle its consecutive payload pairs repeat forever; a person types novel pairs indefinitely. Measured on the corpus before implementing:

Three implementation details carry weight. It is judged causally — each transition is scored against history from before it, then folded in — so training and live inference see identical values. It carries the transition across the window boundary, since that pair is real. And the remembered set is capped, because a bulk device emits thousands of distinct random payloads per second; once full, novelty keeps reporting ≈1.0, which is the correct answer for genuinely random data.

Impact

This feature took mimicry detection from 0 % to 100 %, and overall detection from 86.7 % to 100 %. It also made the extractor stateful: one instance belongs to one device session, and must be reset between them or the next device inherits the previous one's history.

Declared overfitting

This feature was designed after seeing which attack was failing, using knowledge of how the simulator builds it. The defence is that the constraint is real — an injection payload must type specific commands and cannot randomise its sequence without ceasing to be a payload — but the honest claim is that it raises the attacker's cost, not that it solves the problem.

10Class–behaviour mismatch

Catch a device doing something its declared class should not do.

allowed := ⋃ { EXPECTED[i.class] : i ∈ visible_at(t) } HID (0x03) → {intr, control} Mass storage (0x08) → {bulk, control} Video (0x0E) → {iso, control, intr} Audio (0x01) → {iso, control} CDC (0x02) → {bulk, intr, control} mismatch := |{ e : e.ttype ∉ allowed }| / n

This is the feature that makes descriptor spoofing useless. A device may claim to be a keyboard, but if its URBs are bulk OUT the term fires at 1.0. Control transfers are permitted for every class, because every device performs control traffic during enumeration and that is not an attack.

It resolves against interfaces visible at the end of this window, so a device that legitimately gains an HID interface stops being flagged from that moment on — while one that never declared HID keeps being flagged.

L3 · Stage 1

Memoryless anomaly scoring

src/iudbms/stage1/model.py

Two questions per window, fused into one score. The population model asks "is this unusual for anything of this claimed type?"; the device model asks "is this unusual for this device?" Stage 1 sees one window at a time and has no memory of sequence, which is exactly its limitation.

11Standardisation with floor and clip

Put 28 features on a common scale without letting one dominate.

µ := mean(X_benign) σ := max( std(X_benign), 0.01 ) ← SD_FLOOR z := clip( (x − µ) / σ, −10, +10 ) ← STD_CLIP
This floor fixed a real defect

Three features are exactly constant across benign traffic — class_behaviour_mismatch, late_iface_flag and n_interfaces are 0 or 1 for every benign device, by construction. Dividing by σ + 10⁻⁶ turned a single 0→1 flip into a standardised value near 10⁶ that swamped all 28 dimensions. It surfaced in the dashboard as alert evidence reading late_iface_flag 4472091.23.

Such a feature is informative when it changes — that is the whole point of the mismatch term — so the fix bounds its influence rather than removing it. A binary flip is now ≈100 σ, clipped to 10: still decisively anomalous, no longer the only thing the model can see.

12Class-conditioned Isolation Forest

Population-level outlier scoring, trained on benign windows only.

group(device) := composite | hid | storage | av | other ← from interfaces declared at ENUMERATION (t=0) one forest per group with ≥ 30 benign windows, else the generic forest raw := −score_samples(z) ← higher = more anomalous a := raw / p99(raw over benign) ← calibrated to benign scale
n_estimators200 trees max_samplesmin(512, n) contamination0.02

An Isolation Forest isolates points by random axis-aligned splits; anomalies need fewer splits to separate, so path length is the score. It is unsupervised, which matters because Stage 1 must be trainable without any attack labels — an operator has benign traffic, not a labelled attack corpus.

Class conditioning does real work. A single global model conflates a 125 Hz mouse with a human typist, so ordinary mouse traffic reads as anomalous. Conditioning on the device's declared family gives each a reference population it actually belongs to.

Enumeration-time grouping is deliberate

The group comes from interfaces declared at t = 0, not from whatever the device eventually exposes. A device that enumerates as storage and later grows an HID interface is still scored against the storage population — which is exactly what makes its injected keystrokes anomalous rather than expected. It is also what a defender knows at authorisation time.

13Online EWMA device baseline

Learn what normal looks like for this specific device, incrementally.

d := x − mean mean := mean + α·d var := (1 − α)·(var + α·d²) ← incremental EWMA variance initial: mean ← first observation, var ← 0.25, α = 0.15

This is novelty pillar N2. A per-device baseline answers a question the population model cannot: a device may be entirely normal for its class and still be behaving unlike itself. Exponential weighting means recent windows dominate, so the baseline tracks drift without unbounded memory — it needs O(features) state per device, not a growing history.

The variance recursion is the standard exponentially-weighted form, which updates mean and variance in a single pass without storing past samples.

14Top-k deviation statistic

Reduce 28 per-feature deviations to one number, plus an explanation.

zᵢ := |xᵢ − meanᵢ| / √( max(varᵢ, 0.05) ) ← VAR_FLOOR d := mean of the 3 largest zᵢ explanation := the names of those 3 features

Taking the mean of the three largest, rather than the mean of all or the single maximum, is a deliberate middle ground: averaging all 28 dilutes a genuine spike in one feature, while the single maximum is dominated by whichever feature happens to be noisiest. It also yields a free explanation — those three feature names ship with every alert, and are what make the generated rule auditable.

The variance floor was not optional

Many features are near-constant for a given device — a keyboard's frac_iso is always 0 — so their EWMA variance collapses toward zero and any change produces an enormous z. Measured without a floor, the benign device deviation had median 0.8 but a 99th percentile of 90.8 and a maximum of 1267. Since calibration divides by that 99th percentile, the device term contributed about 0.009 to a score bounded at 1.0 — pillar N2 was in the architecture diagram and absent from the arithmetic. The floor was swept over {0, 0.01, 0.05, 0.1, 0.25, 0.5}; 0.05 maximised Stage-1 AUC and cut benign window FPR from 0.26 % to 0.07 %.

15Score fusion

Combine population and device evidence into one bounded score.

s := clip( 0.55 · clip(a, 0, 3)/3 + 0.45 · clip(b, 0, 3)/3 , 0, 1 ) a = population (forest) term, calibrated by benign p99 b = device (baseline) term, calibrated by benign p99

Both terms are divided by their own 99th percentile on benign traffic, so each contributes on a comparable scale regardless of its raw units. Clipping at three times that percentile prevents a single extreme window from saturating the fused score, and the near-equal weights reflect that neither question is more important than the other.

The weights are a parameter, not a constant

0.55/0.45 is Stage1.DEFAULT_WEIGHTS, not a hard-coded split — weights=(1.0, 0.0) renormalises to forest-only on the identical score scale, which is exactly what novelty pillar N2's ablation uses to isolate the device-baseline term's contribution without changing anything else about how a score is computed. Measured result: removing it changes session detection by less than one session either way, and its AUC contribution is negative at both the fused and Stage-1-only level — N2 is not supported by this corpus. The temptation to sweep this weight until it looks supported was deliberately not acted on: that would be fitting the conclusion, not measuring it.

16Baseline update gating

Stop an attack from teaching the baseline that it is normal.

update the baseline with this window iff s < 0.55 or n < 4 GATE WARMUP

An online baseline that absorbs every window is trivially defeated by a slow ramp: increase the attack rate gradually and the baseline follows, so the deviation never grows. Refusing to learn from windows that already score as anomalous breaks that. The warm-up exemption lets a newly attached device establish a baseline at all — before four windows the deviation is reported as zero rather than trusted.

L3 · Stage 2

Temporal modelling and enforcement

src/iudbms/stage2/ · src/iudbms/policy/

Stage 1 can only ask whether a given second looks odd. A staged payload that idles as a human-driven keyboard and then fires looks, second by second, like two individually plausible devices — only the transition is anomalous. This is the pillar the evidence supports most clearly: memoryless scoring reaches 11.7 % session detection, the full system 100 %.

17Left-padded rolling sequences

Give the model the last K windows without leaking the future.

for window w: chunk := X[max(0, w−K+1) … w] if |chunk| < K: left-pad by repeating chunk[0] K = 10 windows; each row = 28 features ++ its Stage-1 score → 29 dims

Padding by repetition rather than zeros keeps early windows on the same scale as later ones, so a device's first seconds do not present as a discontinuity. The construction is strictly causal — the sequence for window w never contains a row from after w — which is what lets the live detector produce numerically identical scores to the offline evaluation.

K was swept, not assumed

K ∈ {10, 20, 30} × hidden ∈ {32, 64} on a held-out selection split gave identical detection at every setting, while longer horizons slightly reduced AUC and pushed latency from 3.6 s to 4.8 s. More memory was never the lever; the missing ingredient was a feature that carried cross-window information at all (algorithm 09).

18LSTM classifier

Emit P(malicious) for the newest window given the last ten.

iₜ = σ(Wᵢ·[xₜ, hₜ₋₁] + bᵢ) input gate fₜ = σ(Wᵧ·[xₜ, hₜ₋₁] + bᵧ) forget gate — bias initialised to 1 gₜ = tanh(Wᵗ·[xₜ, hₜ₋₁] + bᵗ) candidate cell oₜ = σ(Wₒ·[xₜ, hₜ₋₁] + bₒ) output gate cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ gₜ hₜ = oₜ ⊙ tanh(cₜ) P(malicious) = σ( Wₖ·hₖ + bₖ ) ← linear head on the LAST timestep
layers1 hidden32 input29 optimiserAdam, lr 2·10⁻³ grad clip‖g‖ ≤ 5

The gating is what makes an LSTM rather than a plain recurrent network the right tool: the forget gate lets the cell carry information across the whole sequence without the gradient vanishing, which is the entire requirement when the signal is "this device behaved one way and now behaves another." Initialising the forget-gate bias to 1 starts training in a remember-by-default regime, a standard trick that keeps gradients flowing early.

Labelling is what forces it to learn transition rather than identity. The label applies from attack onset onward, so pre-onset windows of a malicious session are labelled benign — the same device, the same descriptor, the same VID:PID appears on both sides of the boundary, so device identity carries no information about the label.

19Class-weighted loss

Stop the model reaching high accuracy by predicting "benign".

pos_weight := (N − P) / P ← negatives per positive L := BCEWithLogits(logits, y, pos_weight)

Post-onset windows are the minority — most windows of most sessions are benign — so an unweighted model can score well by never predicting an attack. Weighting the positive class by the negative-to-positive ratio makes a missed attack window as expensive as a false alarm. Training logs report recall on the positive class alongside accuracy, for the same reason: accuracy alone is misleading under imbalance.

20k-of-n persistence gate and escalation

Turn a noisy per-window score into a decision worth acting on.

history := sliding window of the last n indicators (s₂ ≥ θ) fire iff Σ history ≥ k escalation: observe --k of n--------------→ THROTTLE (severity high) throttled --2k cumulative hits--→ DEAUTHORIZE (severity critical) deployed: k = 4, n = 6

This is the main false-positive control and it is what makes automatic revocation contemplatable at all. A single anomalous window never triggers anything. Per-window false positives compound across a session: at 0.5 % per window over ~60 windows almost every benign session eventually trips, which is why the gate and not the threshold does the heavy lifting.

Its value is visible in the mimicry replay, where the score crosses the threshold, falls back below it, and crosses again. Without persistence that would flap; with it, the device escalates once.

Eval

Measurement and its discipline

eval/

These are algorithms too, and they are where a project like this most easily fools itself. Three of the eight defects found were in this layer rather than in the detector.

21Threshold calibration at a target FPR

Derive the decision boundary from data instead of picking a number.

θ := quantile( scores over CALIBRATION benign windows, 1 − target_FPR ) deployed: target_FPR = 10⁻⁴ → θ = 0.9209

The threshold is not a magic constant: it is the probability that produces a stated per-window false-positive rate on held-out benign traffic. That is what makes enforcement learned rather than a static rule, and it is why every generated rule carries the trigger that produced it.

Calibration and scoring must be disjoint

If the threshold is fitted on the same sessions it is measured on, the false-positive rate hits its target by construction and every configuration looks equally good. The evaluation refuses to run when the two splits are the same, because naming them fit/val/test rather than by role invited exactly that bug.

22Session-stratified splitting

Prevent the single easiest way to report fake accuracy.

group sessions by profile within each profile: 70 % train / 30 % test carve 20 % of train as the calibration split NEVER split by window

Consecutive windows of one session are near-duplicates of each other, so a window-level split puts almost-identical rows in both training and test and inflates every metric. Stratifying by profile additionally guarantees each attack family appears in training, so a test-set profile is never one the model has literally never seen.

Hyperparameter sweeps go further and never construct the test split at all: three disjoint inner splits — train, calibrate, select — are carved out of the non-test sessions.

23Two-sample Kolmogorov–Smirnov leakage audit

Prove benign and malicious sessions are not separable on anything but behaviour.

D := maxₓ | F₁(x) − F₂(x) | ← largest CDF gap D_crit := 1.63 · √( (n+m) / (n·m) ) ← α = 0.01 flag when D > D_crit, per profile — on duration, window count, and VID:PID

The KS statistic makes no distributional assumption, which is what is wanted here: the question is whether two samples came from the same distribution at all, not whether their means differ.

Aggregate agreement is not evidence

An earlier duration leak survived a round of fixing because aggregate means matched — benign 63.7 s against malicious 63.9 s — while a single profile still drew from 65–85 s against everyone else's 40–85 s. The audit therefore runs per profile, and a test re-introduces the original bug to prove the audit still catches it. An audit that cannot fail manufactures confidence rather than providing it.

Eval

Model-family comparison — does each chosen algorithm earn its place?

eval/model_zoo.py · make zoo

Every algorithm above this point was chosen without ever being tested against an alternative. This section is that test: eight candidate models, scored by the identical machinery as the deployed system, on a selection split so the comparison can drive a real decision — --on test exists only for exploratory use, because choosing a model from a test-scored table is selecting on test. Fairness note: Stage 1 candidates train on benign windows only and never see an attack label; every Stage 2 candidate is supervised. Comparing across that line measures the cost of the labelling constraint, not which family is "better" in general.

26aLocal Outlier Factor, One-Class SVM, Elliptic Envelope

Three more ways to ask "is this window unusual?" without attack labels.

LOF(x) := local density of x vs. local density of its k=20 nearest neighbours ← an outlier sits in a sparser neighbourhood than its neighbours' neighbourhoods OCSVM(x) := signed distance from a learned boundary enclosing "normal" in a kernel-transformed space (RBF kernel, ν=0.02 controls the boundary's slack) EllipticEnvelope(x) := Mahalanobis distance from a robust estimate of the benign distribution's centre and covariance (assumes normal features are roughly Gaussian)
LOFn_neighbors=20, novelty=True OCSVMkernel=rbf, ν=0.02, γ=scale EllipticEnvelopecontamination=0.02, support_fraction=0.9

Three genuinely different anomaly-detection principles: LOF asks about relative local density, One-Class SVM learns an explicit boundary, Elliptic Envelope assumes the benign class is (roughly) one Gaussian blob and measures distance from its centre. None of the three construct an ensemble of random splits the way Isolation Forest does.

Why One-Class SVM collapsed

An RBF kernel needs its bandwidth tuned to the data's actual scale; left at scikit-learn's default heuristic on 28-dimensional standardised features, the learned boundary ended up so loose that almost every window — benign or not — fell outside it. This is a known failure mode of the algorithm on unscaled or oddly-shaped feature spaces, not a defect in the comparison; it is reported rather than tuned away, because the incumbent needed no such rescue.

26bGRU — the LSTM's simpler cousin

Test whether the LSTM's extra gate (four gates vs. three) is buying anything.

zₜ = σ(Wᵢ·[xₜ, hₜ₋₁]) update gate rₜ = σ(Wᵧ·[xₜ, hₜ₋₁]) reset gate h̃ₜ = tanh(Wᵗ·[xₜ, rₜ⊙hₜ₋₁]) hₜ = (1−zₜ)⊙hₜ₋₁ + zₜ⊙h̃ₜ ← no separate cell state; h IS the memory

A GRU merges the LSTM's forget and input gates into one update gate and drops the separate cell state entirely — fewer parameters, same basic idea of learning what to keep and what to overwrite at each step. Same input (28 features + Stage-1 score, sequence length 10), same training regime, same class-weighted loss.

Result

AUC 0.9790 vs. the LSTM's 0.9798, detection tied at 88.0%. Within the selection split's noise floor. The extra gate is not earning its parameter budget on this task.

26cDilated 1-D convolution — a temporal model with no recurrence at all

If recurrence itself (not just "reading a sequence") is what matters, a convolution should do noticeably worse.

layer 1: Conv1d(kernel=3, dilation=1) → ReLU ← sees 3 adjacent windows layer 2: Conv1d(kernel=3, dilation=2) → ReLU ← sees 7 windows, with gaps AdaptiveMaxPool1d(1) ← collapse the time axis to one vector Linear → P(malicious)

Dilation widens a convolution's effective reach across time without adding layers — the second layer's receptive field covers the whole 10-window sequence despite a kernel width of only 3. Unlike an LSTM, a convolution has no notion of "step 1 happens before step 2 and I carry a memory forward" — it looks at fixed local neighbourhoods in parallel and pools the result. It is temporal (it uses the whole window) without being recurrent (no state is carried step-by-step).

Result

AUC 0.9753, detection tied with the LSTM at 88.0% — but roughly 5–7× slower to train (37.8s vs. 6.8s) because of the extra convolution arithmetic. Confirms the earlier finding precisely: sequence context is what matters; recurrence specifically is not required to extract it.

26dGradient-boosted trees over a flattened sequence

The cheapest possible way to hand a model the same 10-window information.

flatten: [10 windows × 29 features] → one 290-number row per example fit: histogram-based gradient boosting, 200 rounds, class_weight=balanced

No architectural notion of order at all — the 290 numbers are just 290 columns to a tree ensemble, which is free to learn "column 261 (the most recent window's cv_iat) matters more than column 1" if the data supports it, but has no built-in bias toward treating nearby columns as temporally related the way a CNN or RNN does.

Result

AUC 0.9770, detection 86.0% — one selection-split session behind the LSTM, at roughly a quarter of the training time (1.7s vs. 6.8s). Losing the explicit sequence structure costs a small amount, but far less than expected: most of the value in "reading 10 seconds" survives even when the model is never told those 290 numbers form an ordered story.

26eThe architecture control — one window, no sequence, no pipeline

Isolate the value of temporal context itself, stripped of everything else.

input: the 28 raw features of ONE window only (no Stage-1 score, no history) fit: HistGradientBoosting or RandomForest, supervised, 200 estimators

This is the sharpest test in the whole comparison — remove Stage 1 entirely and remove the 10-window sequence entirely, leaving a single supervised classifier that sees exactly one second and nothing else, the same information Isolation Forest sees but with attack labels this time.

What this actually isolates

Two numbers worth separating. First: a supervised single-window model (80.0%) massively outperforms the unsupervised single-window Stage 1 (0.0% detection at the deployed threshold on the same corpus) — that gap is the price of the constraint that Stage 1 may never see an attack label. Second: adding back temporal context (the full pipeline, 88.0%) gains a further 8 points over the best single-window supervised model — that gap is what sequence modelling contributes once the labelling handicap is already paid for. Novelty pillar N3 is a claim about this second gap, and it survives.

24Noise-floor-aware model selection

Stop a sweep from recommending a change on a margin too small to mean anything.

noise := 1 / (attack sessions in the selection split) ← smallest resolvable difference challenger wins iff detect(challenger) − detect(incumbent) > noise otherwise: KEEP the incumbent, regardless of which one ranks higher on the grid

A detection rate computed over n sessions is a count divided by n — it physically cannot represent a difference smaller than one session, 1/n. A sweep that reports "the winner" from a ranked grid, without checking whether the winning margin clears that floor, is reporting noise as if it were a finding.

This guard exists because it was violated once, for real

A longer sequence horizon (K=30) won a 50-attack-session selection split by exactly one session — a 2.0% margin, precisely at the noise floor. Applied and run against the real held-out test split, it scored five points worse than the incumbent (K=10), and one attack class's detection fell from 40% to 10%. The fix compares every challenger against the deployed configuration specifically (--incumbent) rather than only ranking the grid, and requires the margin to exceed 1/n before recommending a change. Nothing is ever applied automatically — the sweep prints a recommendation; deploying it is a separate, deliberate step.

25Corpus / simulator fingerprinting

Stop a cached dataset from silently outliving the code that generated it.

fingerprint := SHA-256( bytes(capture/simulator.py) ++ bytes(features/extractor.py) )[:16] on load: reject the cache iff stored_fingerprint ≠ current_fingerprint

A cached corpus (corpus_cache.npz) exists purely to avoid re-generating twelve million lines of usbmon text on every run — but a cache is only valid for the code that produced it. Hashing the exact source files that determine a window vector's content means any edit to either one invalidates every existing cache automatically, with no separate versioning scheme to remember to bump.

This is not a hypothetical failure mode

Checking only the data-contract version (a coarser, hand-incremented number) was the original approach, and it let a corpus generated by one version of the attack simulator get silently scored as if it still represented the current adversary — precisely while this project's own mimicry attack was being made more realistic. The fingerprint check has already fired for real once since being added, forcing a rebuild rather than a silently stale evaluation.

Every formula above is implemented in the repository and exercised by the test suite; parameter values are the deployed ones, reproducible with make eval at seed 7, and the model comparison with make zoo.
